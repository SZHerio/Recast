# M2: протокол классификации runtime-форм

Статус: **`USER_GATE_PENDING`**  
Build: **`IF-M2-0001`**

Этот документ определяет, как закрывается динамическая часть аудита всех руд, слитков, самородков, пылей, пластин и жидкостей. Владелец сборки не заполняет таблицу вручную: он передаёт вывод двух штатных команд KubeJS, после чего Codex извлекает ID, классифицирует их и обновляет реестры без запуска Minecraft со своей стороны.

## 1. Входные данные

В одном и том же тестовом запуске выполнить:

```text
/kubejs dump_registry minecraft:item
/kubejs dump_registry minecraft:fluid
```

Передать полный `latest.log` либо console log, содержащий строки от заголовка каждого dump до `Total: ... entries`. Вместе с ним нужны Build ID, список активных JAR из того же профиля и отметка о том, менялся ли модлист после `IF-M2-0001`.

## 2. Область отбора

Из полного реестра извлекаются:

- все item/fluid ID namespaces установленных технологических модов;
- vanilla-формы, участвующие в их рецептах;
- руды, raw-формы, слитки, самородки, блоки хранения, пыли, малые пыли, пластины/листы, стержни, провода, шестерни, расплавы, растворы, газы, пар и технологические жидкости;
- необычные формы, которые дают обход worldgen, эпохи, чистоты, стоимости или отходов;
- формы, принятые pack-тегами `industrial_frontier:materials/*`.

Декоративные предметы не исключаются молча: им присваивается `OUT_OF_SCOPE_WITH_REASON`.

## 3. Допустимые решения

Каждая отобранная строка получает ровно один статус:

| Статус | Значение |
|---|---|
| `CANONICAL` | точный выход владельца вещества/процесса |
| `ACCEPTED_INPUT` | допустимый эквивалентный вход, который не становится каноническим выходом |
| `SPECIALIZED` | физически или химически особая форма, которую нельзя безопасно унифицировать |
| `DISABLED_DUPLICATE` | необъяснённый дубль либо обход; источник/рецепт должен быть выключен |
| `OUT_OF_SCOPE_WITH_REASON` | форма не участвует в производственной прогрессии, причина записана явно |

## 4. Машинная строка результата

Итоговая запись должна содержать:

```json
{
  "runtime_id": "namespace:path",
  "registry": "minecraft:item",
  "material_ref": "industrial_frontier:substance/example",
  "form": "PLATE",
  "decision": "CANONICAL",
  "owner_domain_ref": "industrial_frontier:domain/example",
  "available_epoch": "P3",
  "accepted_tag_refs": [],
  "process_refs": [],
  "bypass_decision_ref": null,
  "reason_ru": "Почему эта форма существует и как используется",
  "evidence": {
    "build_id": "IF-M2-0001",
    "source": "KubeJS runtime registry dump"
  }
}
```

Если runtime-ID не сопоставляется существующему веществу, сначала создаётся или уточняется паспорт. Нельзя подставлять ближайший материал только ради закрытия счётчика.

## 5. Проверки после классификации

- число распознанных строк равно числу отобранных ID;
- неклассифицированных строк `0`;
- у каждого `CANONICAL` ровно один владелец;
- `ACCEPTED_INPUT` не используется как случайный output;
- каждый `DISABLED_DUPLICATE` связан с конкретным конфигом или recipe-removal;
- специализированные формы не входят в общие теги без доказанной эквивалентности;
- нет положительного материального цикла между формами;
- эпоха формы не раньше источника вещества и владельца процесса;
- все русские термины соответствуют [`RU_STYLE_GUIDE.md`](RU_STYLE_GUIDE.md).

Gate закрывается только после обновления `m2_material_forms.json`, связанного bypass/worldgen-решения, пользовательской повторной проверки затронутого рецепта и чистого M2-validator/lint.
