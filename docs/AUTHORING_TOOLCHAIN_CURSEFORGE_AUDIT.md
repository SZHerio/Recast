# CurseForge-аудит вспомогательного авторского стека

Дата аудита: **1 августа 2026 года**  
Платформа: **Minecraft 1.20.1, Forge 47.4.22**  
Статус: **решения для внедрения; JAR в рамках этого аудита не устанавливались**  
Ограничение: **Codex не запускает Minecraft. Все игровые команды, редакторы внутри игры и проверки выполняет владелец сборки.**

Этот документ определяет инструменты, которые ускоряют создание рецептов, квестов, русской локализации, меню и уникальных производственных объектов. Это не перечень случайных QoL-модов для игрока: у каждого принятого компонента есть конкретный авторский контракт и владелец данных.

## 1. Итоговое решение

### Первая авторская волна M1

Добавить после фиксации exact-файлов CurseForge в авторском source registry:

1. FTB Library, FTB Teams и FTB Quests;
2. FTB XMod Compat и FTB Filter System;
3. Quests Additions;
4. KubeJS Create;
5. LootJS;
6. Paxi;
7. Almost Unified со строгим белым списком;
8. ProbeJS только в авторский/dev-профиль;
9. FTBQ Better Fluids через отдельный пользовательский compatibility-gate;
10. FTB Quests Optimizer не добавлять к выбранному FTB Quests `2001.4.22`; вернуться к вопросу только при измеренной проблеме и совместимом релизе.

Уже установленные KubeJS, Rhino, KubeJS Additions и PonderJS сохраняются. CraftTweaker, CreateTweaker и другие параллельные владельцы тех же рецептов не добавляются.

### Более поздние специализированные волны

- MoreJS — при создании городской экономики, управляемой торговли и структурного лута;
- In Control! — после фиксации биомов и фауны, только для спавна и опыта;
- Default Options + Balm — после стабилизации клиентских настроек и клавиш;
- FancyMenu + Drippy Loading Screen + Konkrete + Melody — единым закреплённым комплектом для меню и загрузки;
- Throughput Quest — один экспериментальный AE2-пилот для доказательства реальной производительности фабрики;
- Multiblocked2 + LDLib — только один пилот уникальной водоочистной станции, не новая универсальная технологическая лестница;
- адаптеры KubeJS для TFMG или Immersive Engineering — только после принятия соответствующего контентного мода и отдельной проверки версии.

## 2. Легенда решений

| Статус | Значение |
|---|---|
| `KEEP` | Уже присутствует и остаётся частью авторского фундамента |
| `MAIN-M1` | Включить в первую авторскую волну |
| `MAIN-LATE` | Принят, но добавляется только в момент появления его предметной области |
| `GATED` | Полезен, но сначала нужен узкий пользовательский тест совместимости |
| `DEV` | Инструмент автора/диагностики; не обязан попадать в публичный игровой профиль |
| `PILOT` | Один ограниченный прототип; расширение разрешено только после успешной проверки |
| `REJECT` | Не добавлять: дублирование, хрупкость или отсутствие уникальной роли |

## 3. Единые владельцы данных

| Домен | Единственный владелец | Что запрещено дублировать |
|---|---|---|
| Обычные рецепты, теги, скрытие JEI, pack-события | KubeJS; нативный API GTCEu внутри KubeJS | Те же рецепты в CraftTweaker, datapack и другом скриптовом слое |
| Процессы Create | KubeJS Create | Ручной набор разных нестабильных JSON-обёрток для тех же типов рецептов |

| Сложные варианты предметных задач | FTB Filter System | Одновременное использование старого Item Filters в новых квестах |
| Pack-native datapack/resource pack | Paxi | Open Loader, Load My Resources и ручные копии одного пакета в нескольких каталогах |
| Простая унификация массовых форм | Almost Unified | Унификация специальных топлив, изотопов, газов и доменных промежуточных веществ без паспорта |

| Уникальные авторские multiblock | Multiblocked2, только после пилота | Custom Machinery, Masterful Machinery и другие framework одновременно |

Главный принцип: вспомогательный мод принимается не потому, что умеет много, а потому, что закрывает одну ещё не занятую область и сокращает объём хрупкого собственного кода.

### Почему выбран FTB Filter System, а не Item Filters

Для Forge 1.20.1 существует официальный файл FTB Filter System `20.0.1`; актуальный FTB Quests прямо называет его рекомендуемой альтернативой старому Item Filters при наличии FTB XMod Compat 2.1.0+. Поэтому новый квестбук строится на FTB Filter System. Item Filters остаётся только вариантом миграции чужих готовых глав, если конкретный импорт действительно на него завязан.

## 5. Квестовые расширения с отдельными воротами

### FTBQ Better Fluids — принять после узкого теста

[FTBQ Better Fluids](https://www.curseforge.com/minecraft/mc-mods/ftbq-better-fluids) `ftbq_better_fluids-1.0.1.jar` добавляет задачу `Fluid+`. Она обнаруживает жидкость в предметах с Forge fluid handler — ведре, ячейке, баке, барабане — и позволяет открыть рецепт жидкости из квеста. Для сборки с химической академией это намного лучше требования «принеси ведро кислоты».

Риск: проект новый и имеет небольшую пользовательскую базу. Перед широким применением владелец проверяет:

1. GTCEu fluid cell;
2. бак GTCEu;
3. бак Create;
4. обычное ведро;
5. OR-список двух эквивалентных жидкостей;
6. одиночную игру и командный прогресс.

`Fluid+` используется для доказательства наличия или знакомства с веществом. Контракт на фактическую сдачу партии использует штатную consuming-задачу или явно описанную поставку: игрок не должен случайно терять производственный запас.

### FTB Quests Optimizer — не принимать в текущий стек

[FTB Quests Optimizer](https://www.curseforge.com/minecraft/mc-mods/ftb-quests-optimizer/files/all?page=1&version=1.20.1) `2.1.0` заявляет поддержку FTB Quests `2001.4.21`, тогда как закреплён `2001.4.22`. Официальный changelog FTB Quests также предупреждает о риске нестабильности стороннего optimizer. Поэтому текущий статус — `REJECT/HOLD`: сначала измеряется реальная проблема на штатном FTB Quests, затем рассматривается только явно совместимый релиз.

### Throughput Quest — только производственный пилот

[Throughput Quest](https://www.curseforge.com/minecraft/mc-mods/throughput-quest) `throughput_quest-1.20.1-1.0.0.jar` проверяет поток предметов в сети AE2. Это редкий способ превратить квест Factorio-типа из «накопи 10 000 деталей» в «поддерживай 64 детали/мин», то есть вознаградить хорошую фабрику, а не сундук ресурсов.

Статус `PILOT`: версия 1.0.0, область ограничена AE2. Сначала один необязательный поздний квест; при нестабильности его заменяет проверка буферной партии и понятный ручной расчёт производительности.

### Quests Additions — правила против гринда

- `Place/Structure` проверяет функциональный объект один раз, а не сотни декоративных блоков.
- `Timer` используется только для короткого доказательства устойчивой работы, если это не создаёт ожидание без действий.
- `Repeatable` разрешён для добровольных городских контрактов с контролем экономики, не для основной прогрессии.
- `Break` не заставляет разрушать уже построенную фабрику; подходит для учебного демонтажа или аварийного ремонта.

## 7. Один framework авторских машин

### Выбор: Multiblocked2, но не как обязательная база

Единственный кандидат — [Multiblocked2](https://www.curseforge.com/minecraft/mc-mods/multiblocked2) `multiblocked2-1.20.1-1.0.38.a-forge` с совместимой версией [LDLib](https://www.curseforge.com/minecraft/mc-mods/ldlib/files/all?page=1&version=1.20.1).

Он выбран потому, что поддерживает предметы, жидкости, FE, энергию GTCEu и механику Create и позволяет описывать действительно уникальные крупные объекты. Но visual editor находится в игре, поэтому внедрение делится:

1. Codex проектирует назначение, структуру, I/O, рецепты, локализацию и диагностический квест.
2. Владелец создаёт или импортирует пилот, запускает редактор и экспортирует определение.
3. Codex сопровождает экспортированные JSON/ресурсы и связывает их с KubeJS/квестами.
4. Владелец проверяет сборку multiblock, сохранение мира, перезагрузку и производительность.
5. Только после успешного пилота разрешается второй объект.

Первый пилот — **городская водоочистная станция**:

`сырая вода + коагулянт + энергия → очищенная вода + влажный осадок`.

Она связывает GT-химию, город, сельское хозяйство, канализацию и экологию. Multiblocked2 не получает универсальных дробилок, печей, химических реакторов или генераторов, уже принадлежащих другим доменам.

Резерв возможных объектов после пилота: канализационный комплекс, подстанция, мусоросортировочный завод, атмосферная установка. Никакие четыре объекта не разрабатываются одновременно.

## 10. Русская локализация инструментов

Полное русское покрытие остаётся релизным gate и распространяется на весь новый стек:

1. Для каждого закреплённого JAR сравниваются `en_us.json` и штатный `ru_ru.json`.
2. Недостающие ключи попадают в авторский resource pack под namespace исходного мода.
3. Авторские квесты с начала используют стабильные ключи, а не вшитые английские строки.
4. Названия собственных машин, сообщений ошибок, подсказок JEI/Jade и элементов меню входят в тот же отчёт покрытия.
5. Runtime- и AI-переводчики не используются: результат должен быть детерминированным и редакторски проверенным.

[FTB Quest Localizer](https://www.curseforge.com/minecraft/mc-mods/ftb-quest-localizer) допускается только как временный инструмент миграции. Его экспорт заменяет quest-файлы, поэтому команду выполняет владелец лишь на копии, после резервного сохранения и обязательного diff. Для новых глав предпочтительно сразу вести translation keys вручную.

## 11. Файловые контракты

```text
kubejs/
  startup_scripts/        # только реестр pack-native KubeJS-контента
  server_scripts/         # рецепты, теги, события, интеграции
  client_scripts/         # JEI, tooltip и клиентские KubeJS-правки

config/ftbquests/quests/  # топология, задачи, награды и зависимости квестов

config/paxi/
  datapacks/              # pack-native vanilla data, не копии KubeJS-рецептов
  resourcepacks/          # RU-overrides, шрифты, UI, иконки и авторские ассеты

config/almostunified/     # только allow-list одобренных паспортами массовых форм
config/incontrol/         # только spawn/XP, если мод принят
config/fancymenu/         # макеты и локальные UI-ассеты
config/drippyloadingscreen/
```

Точный каталог экспортов Multiblocked2 фиксируется только после пилота и аудита формата выбранной версии. До этого в основной архитектуре не создаются вымышленные пути.

## 12. Порядок внедрения

1. Зафиксировать полный manifest и резервную копию снимка.
2. Добавить FTB Library → Teams → Quests → XMod Compat → FTB Filter System.
3. Пользовательски проверить пустую книгу, команды и один фильтр.
4. Добавить Quests Additions и один городской учебный объект.
5. Добавить KubeJS Create и проверить только используемые типы рецептов.
6. Добавить LootJS; построить реестр изменяемого лута.
7. Добавить Paxi; перенести один минимальный RU resource pack и один datapack.
8. Настроить Almost Unified на нескольких безопасных материалах; пользователь делает JEI-diff.
9. Добавить FTBQ Better Fluids; пройти шесть узких проверок.
10. Не добавлять FTB Quests Optimizer; сравнивать производительность штатного FTB Quests только после появления сотен задач.
11. Установить ProbeJS в dev-профиль; владелец создаёт dump.
12. Только затем массово писать квесты и межмодовые рецепты.
13. MoreJS, In Control и Default Options вводить в момент появления их контента.
14. Multiblocked2 не трогать до утверждённого проекта водоочистной станции.

Каждый шаг передаётся владельцу отдельно. При ошибке откатывается только последний добавленный слой; Minecraft Codex не запускает.

## 14. Definition of Done авторского фундамента

- каждый выбранный сторонний JAR скачан из точного CurseForge-файла и закреплён по project ID, file ID, CDN URL и SHA-256; видимость в CurseForge App не требуется;
- нет двух владельцев одного recipe/loot/spawn/UI-домена;
- открывается русская глава «Начать здесь» с эталонным пошаговым квестом;
- работает один сложный FTB Filter System filter;
- Fluid+ распознаёт GTCEu и Create-тару либо исключается до исправления;
- KubeJS Create подтверждён на Create 6.0.8 пользователем;
- Paxi доставляет RU resource pack и datapack в новый мир;
- Almost Unified не трогает специальные изотопы, топлива, газы и промежуточные вещества;
- quest-lint и отчёт покрытия `ru_ru` проходят статически;
- владелец не сообщает ошибок этого слоя в логах;
- Codex не запускал игру и не выдаёт непроверенное игровое поведение за подтверждённое.
