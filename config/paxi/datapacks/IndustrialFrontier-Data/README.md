# IndustrialFrontier-Data

Датапак авторских данных сборки. Загружается через Paxi, поэтому его файлы
перекрывают одноимённые файлы модов.

Здесь лежат несколько видов содержимого.

## 1. Авторские теги

`data/industrial_frontier/tags/**` — принимающие теги сборки: палитры эпох,
рационы, категории хранения и мебели. Тег принимает категорию, а не конкретный
предмет: это основа правила против гринда «контракт принимает материал классом».

## 2. Отключение чужой генерации мира

Файлы вида `data/<mod>/forge/biome_modifier/<name>.json` с содержимым
`{"type": "forge:none"}` гасят рудные модификаторы модов, у которых уже есть
владелец. Рудной генерацией владеет GregTech — это решение M0, приведённое в
исполнение в M4 и продолженное в M6 и M7.

Перекрыты: Immersive Engineering (7), NuclearCraft (24), HBM-NTM Rebirth (3),
Creating Space (1 — никель надмирья).

## 3. Перекрытие чужих данных, у которых нет конфигурации

`data/creatingspace/creatingspace/rocket_accessible_dimension/**` и
`data/minecraft/creatingspace/rocket_accessible_dimension/overworld.json`
задают граф маршрутов ракеты Creating Space.

Решение владельца от 3 августа 2026: пунктами назначения владеет GCYR,
Creating Space отвечает за околоземную орбиту и станцию. Планеты двух модов
дублируются, датапака совместимости для этой пары не существует, поэтому
маршруты сведены к паре «Земля ↔ околоземная орбита». Измерения Луны, Марса и
Венеры Creating Space остаются в реестре — они просто перестают быть
достижимыми, — а его конструктор двигателя, химия газов и сборка ракеты не
затронуты ни одним рецептом.

Комментарии в файлах `rocket_accessible_dimension` не ставятся: это чужой
кодек, и лишнее поле в нём — риск без выигрыша. Пояснение живёт здесь.

## 4. Перекрытие чужих рецептов

`data/<mod>/recipes/**` с `"conditions": [{"type": "forge:false"}]` — способ
погасить чужой рецепт, который ссылается на несуществующий предмет. Через
KubeJS такой рецепт не лечится: ошибка возникает при чтении файла, до того как
скрипты получают управление.

## 5. Русская справка ComputerCraft

`data/computercraft/lua/rom/help/**` — полный русский корпус встроенной справки
CraftOS из CC: Tweaked 1.120.0 и дополнений сборки: 100 файлов (99 исходных
разделов CC: Tweaked и `lc_money.txt`) с сохранёнными командами, API,
аргументами, ссылками и разметкой.

Редактируемые тексты находятся в `authoring/computercraft/help/**` в UTF-8.
Runtime-копии здесь записаны в Windows-1251: терминал CC:Tweaked работает с
однобайтовыми глифами и не может напрямую вывести кириллицу Unicode.

Справка находится именно в датапаке, а не в наборе ресурсов. CC: Tweaked
монтирует `data/computercraft/lua/rom/help` через серверный менеджер ресурсов
(`SERVER_DATA`), тогда как каталог `config/paxi/resourcepacks` загружается
только как `CLIENT_RESOURCES` и не может перекрыть ROM-справку.

## 6. Русский интерфейс и диагностика CraftOS

`data/computercraft/lua/rom/**/*.lua` — полные SERVER_DATA-перекрытия 84
изменённых файлов Lua из 102 файлов ROM CC: Tweaked 1.120.0. Переведены вывод
встроенных программ, меню, подсказки, сообщения API, диагностика синтаксиса и
текстовая игра `adventure`. Оставшиеся 18 файлов не копируются: в них нет
переводимого пользовательского текста.

Команды, имена программ и API, события, типы, настройки, пути, URL, шаблоны и
прочие служебные литералы сохранены на английском, чтобы не менять поведение
CraftOS. В `adventure` канонические ключи предметов переведены согласованно во
всех таблицах и сравнениях, английские aliases оставлены для ввода, а названия
оружия сохранены. Семь выражений боевого вывода используют русский канонический
ключ вместо первого английского alias; это единственное разрешённое изменение
кода вне строк.

Русские символы в Lua-строках собраны как десятичные байтовые escape-коды
Windows-1251. Соответствующий атлас `term_font.png` лежит в клиентском наборе
ресурсов IndustrialFrontier-Core. Команды и английские aliases сохранены, так
что для работы со встроенными программами русская раскладка терминала не нужна.
Диапазон байтов, занятый штатной псевдографикой CraftOS, запрещён при сборке;
длинное тире в runtime безопасно заменяется обычным дефисом.

Общий валидатор `tools/build_cc_rom_ru.js` сверяет SHA-256 исходного JAR,
инвентаризацию всех 102 файлов, неизменность кода и комментариев вне строк с
учётом семи перечисленных выражений, число строковых литералов,
Lua-экранирование, `%`-параметры и остаточную английскую прозу.

Полная воспроизводимая сборка запускается командой
`python tools/build_cc_ru.py`: она заново создаёт все 84 Lua-перекрытия,
кодирует справку и строки для терминала, а затем выполняет оба валидатора CC.
