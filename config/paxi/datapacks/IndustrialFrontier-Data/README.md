# IndustrialFrontier-Data

Датапак авторских данных сборки. Загружается через Paxi, поэтому его файлы
перекрывают одноимённые файлы модов.

Здесь лежат три вида содержимого.

## 1. Авторские теги

`data/industrial_frontier/tags/**` — принимающие теги сборки: палитры эпох,
рационы, категории хранения и мебели. Тег принимает категорию, а не конкретный
предмет: это основа anti-grind-правила «контракт принимает материал классом».

## 2. Отключение чужой генерации мира

Файлы вида `data/<mod>/forge/biome_modifier/<name>.json` с содержимым
`{"type": "forge:none"}` гасят рудные модификаторы модов, у которых уже есть
владелец. Рудной генерацией владеет GregTech — это решение M0, приведённое в
исполнение в M4 и продолженное в M6 и M7.

Перекрыты: Immersive Engineering (7), NuclearCraft (24), HBM-NTM Rebirth (3),
Creating Space (1 — никель надмирья).

## 3. Перекрытие чужих данных, у которых нет конфигурации

`data/creatingspace/creatingspace/rocket_accessible_dimension/**` и
`data/minecraft/creatingspace/rocket_accessible_dimension/overworld.json`
задают граф маршрутов ракеты Creating Space.

Решение владельца от 3 августа 2026: пунктами назначения владеет GCYR,
Creating Space отвечает за околоземную орбиту и станцию. Планеты двух модов
дублируются, датапака совместимости для этой пары не существует, поэтому
маршруты сведены к паре «Земля ↔ околоземная орбита». Измерения Луны, Марса и
Венеры Creating Space остаются в реестре — они просто перестают быть
достижимыми, — а его конструктор двигателя, химия газов и сборка ракеты не
затронуты ни одним рецептом.

Комментарии в файлах `rocket_accessible_dimension` не ставятся: это чужой
кодек, и лишнее поле в нём — риск без выигрыша. Пояснение живёт здесь.

## 4. Перекрытие чужих рецептов

`data/<mod>/recipes/**` с `"conditions": [{"type": "forge:false"}]` — способ
погасить чужой рецепт, который ссылается на несуществующий предмет. Через
KubeJS такой рецепт не лечится: ошибка возникает при чтении файла, до того как
скрипты получают управление.
